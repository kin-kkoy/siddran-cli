# Format parity with Siddran-Desktop

Siddran-CLI is a **peer** of the desktop app, not a client of it: both read and write the same
Bag folder. So the governing rule is:

> Anything this crate writes must be byte-identical to what
> `Siddran-Desktop/app/src/desktop/localStore.js` would have written.

Not "equivalent JSON" — identical bytes. If the two disagree, opening a Bag in one app rewrites
files for the other, every save produces spurious diffs, and `reconcileNotes` (the only
destructive code in either app) starts operating on state it did not expect.

## How it is enforced

`crates/core/tests/identity_roundtrip.rs` reads every file in a Bag, re-serializes it from the
parsed model, and asserts the bytes are unchanged.

```bash
cargo test -p siddran-core                                  # committed fixtures
SIDDRAN_TEST_BAG=~/Documents/Siddran cargo test -p siddran-core   # a real Bag, read-only
cargo run -p siddran-core --example bag-check -- ~/Documents/Siddran
```

Status at the end of Phase 0: **51/51 files byte-identical** in `~/Documents/Siddran`,
**49/49** in `~/Documents/Siddran-TestBag`.

The fixtures under `crates/core/tests/fixtures/bag/` were generated by running the desktop's own
`noteToMd` and `JSON.stringify(v, null, 2)` under Node, so they are authoritative rather than a
reimplementation's idea of the format. They deliberately include every trap below.

The suite asserts a minimum number of files compared, so a refactor cannot quietly turn it into
a test of nothing. That failure mode is not hypothetical — the first version of the non-vacuity
check injected the wrong bug and passed, which is why the guard exists.

## The traps, and why each matters

1. **Ids are heterogeneous.** `tasks.siddran` holds `1625` and `"6d5bc24a-…"` in the same array —
   legacy numeric ids beside UUIDs. Modelled as an untagged `Id` enum (`ids.rs`).

2. **`byId` sorts on `String(id)`** (`localStore.js:215`), so `"1000" < "999"`. Sorting
   numerically rewrites the whole file. `byCompletion` likewise sorts `(daily_task_id, date)` as
   strings. Project subtasks are deliberately left in insertion order — do not sort them.

3. **Absent ≠ null ≠ false.** No task row in the real Bag has a `due_all_day` key at all.
   `deadline.js:58` reads `allDay == null && hours === 0 && minutes === 0` as the legacy
   "date-only" signal, so writing `due_all_day: false` would silently convert every legacy
   date-only deadline into a midnight-timed appointment. `skip_serializing_if` is equally wrong,
   because `due_date: null` and `description: null` are genuine explicit nulls. This is why rows
   must be a typed view over an order-preserving raw backing rather than a plain struct.

4. **`tags: ` carries a trailing space** when tags are empty — it comes from the literal in the
   template (`tags: ${note.tags || ''}`), not from the value, so trimming the *value* is not the
   bug; trimming the assembled *line* is. Injecting that bug fails 18 files in the real Bag.

5. **`order:` is emitted only when order is a number** (`localStore.js:46`). Always emitting it
   rewrites every note that lacks one.

6. **No trailing newline** on `.siddran` files, and no blank line between the frontmatter fence
   and the body.

7. **`preserve_order` on serde_json is mandatory.** Without it objects are backed by a `BTreeMap`
   and every key is alphabetized on first write.

8. **Floats.** serde_json writes `2.0` where JS writes `2`. Values parsed from disk keep the
   number type they arrived as, so this only bites on *construction*: never build an integral
   quantity from `f64`. `settings.siddran` carries real floats (`starSize: 1.4`) and both
   emitters agree on shortest-round-trip — the fixture proves it rather than assuming it.

## Known divergences, deliberate

- **Corrupt note ids.** The desktop does `fm.id ? Number(fm.id) : null`, so a hand-edited
  non-numeric id becomes `NaN` and survives (its own comment at `localStore.js:142-144`
  documents the fallout). We treat an unusable id as absent instead. This differs only on files
  a human has already corrupted.

- **Directory iteration order.** `read_dir` order is arbitrary in both apps, and filename
  collision resolution (`Notes.md` vs `Notes-<id>.md`) depends on the order notes are visited.
  We sort before visiting so *our* outcome is deterministic; the desktop's is not.

## Writing: targeted operations, not `reconcileNotes`

The desktop's `reconcileNotes` builds a keep-set from every note in memory and then deletes any
`.md` in `notes/` not in it — plus any *directory* that is not a notebook folder, recursively
(localStore.js:194-206). That is correct there: its in-memory db is the whole truth and it syncs
the entire tree on every flush.

**This crate deliberately does not port it.** A CLI mutates one thing and exits, so a global
keep-set buys nothing and risks everything: any bug in it silently deletes notes, and it would
also delete anything a user or another tool had placed in `notes/` that we failed to model.
Targeted operations — write this file, remove that one — reach the same end state and **cannot
mass-delete by construction**.

What is given up: orphans left behind by a desktop crash are not cleaned. `siddran bag check`
reports them instead, and the desktop reconciles them itself next time it runs. That is the
right trade for a tool that is not the primary editor.

The collision rule is still honoured: the first note to claim `<title>.md` keeps it, a later one
with the same title becomes `<title>-<id>.md`, and "already claimed" means *by a different note*
so saving in place never renames anything.

### Write-side invariants, each with a test

- **Rows sort on write.** `byId` is lexicographic on the *string* id; `byCompletion` on
  `(daily_task_id, date)`. Project subtasks stay in insertion order. A Bag that is already
  unsorted on disk gets sorted — the same thing the desktop's next flush would do, so this is
  convergence, not divergence. (`~/Documents/Siddran-TestBag` really does have unsorted events.)
- **Editing one row changes two lines** — the field and `updated_at` — and the file does not
  change length. Rows nobody touched come back byte-identical, absent keys still absent.
- **Setting a deadline writes both keys.** On a legacy row the *absence* of `due_all_day` is
  meaningful, so changing the date while leaving the flag absent would hand the desktop a modern
  date with legacy semantics.
- **Notes keep numeric ids.** `mdToNote` does `Number(fm.id)`, so a UUID in note frontmatter
  comes back as `NaN` on the desktop side. Only tasks, dailies, projects and events use UUIDs.
  New note ids continue from `max(existing, 1000) + 1` (localStore.js:143-147).
- **Timestamps are JS-shaped.** `now_iso()` emits exactly three fractional digits and a literal
  `Z`; no crate's default `Display` matches, and the Bag compares `updated_at` as text in places.

## When the desktop changes

This contract is checked against the desktop as it was on 2026-09-12. If `localStore.js` changes
how it serializes, this suite keeps passing while silently being wrong. The stronger check —
worth adding before Phase 2 writes land — is a differential test in the *desktop* repo that
hydrates the same fixtures through `localStore` + `memFs`, dumps the result, and diffs it against
this crate's output.
